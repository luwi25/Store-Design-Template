ADMIN PRINT-REQUEST NOTIFICATIONS

One-time setup (GitHub Pages does not deploy the Supabase backend):
1. In Supabase SQL Editor, run the whole store-service/push-notifications.sql.
   Existing store-service/supabase-setup.sql must already have been run.
2. Keys have already been generated for this installation. If setting up a fresh
   checkout without them, run: node store-service/generate-push-keys.cjs
   Open store-service/.push-secrets.env privately. Save its three values as
   Supabase Edge Function secrets: VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY,
   VAPID_SUBJECT. Never paste the private key into frontend code or GitHub.
   Keep the same keys across deployments. The generator refuses to overwrite them.
3. Replace quick-handler's index.ts with the full store-service/index.ts and deploy.
   Keep existing passwords, ALLOWED_ORIGINS and JWT gateway settings unchanged.
4. Publish the website changes to GitHub Pages. Reload the app, sign in as Admin,
   open Store activity, click Enable notifications, and allow the browser prompt.
   Repeat once per Admin device. There is no automatic permission prompt.
5. From a store account on another browser/device, submit a NEW print request.
   Admin receives an alert. Clicking it opens that request (Admin sign-in is
   still required). Approve/reject and the five-hour printing rule work as before.

Notifications work without the poster editor tab open when the browser/OS allows
background delivery. They are best-effort: offline devices, focus modes, browser
settings or an expired subscription can delay/prevent them. Requests always remain
in Store activity. A request retry will not send another notification.

iPhone/iPad: install the website using Safari > Share > Add to Home Screen, then
open that installed app before enabling notifications (iOS/iPadOS 16.4 or newer).
Use the live HTTPS site; an unbuilt local editor does not have the published worker.

Disable notifications in Store activity to remove this device's subscription.
Switching this browser to a store account unsubscribes the device. Enrollment lasts
90 days; disable and enable again to renew. Expired sessions still require sign-in
to review requests, but do not stop alerts on an enrolled Admin device.

If alerts fail: confirm the page says notifications are enabled, the SQL migration
ran, and all three secrets exist. Check quick-handler logs for 'Admin push'.
Delivery failures do not roll back or block print requests. After changing VAPID
keys, enable notifications again on every device. No sales schedule changes needed.
